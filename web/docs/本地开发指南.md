# Dify 前端本地开发指南

本指南将帮助你在本地环境中开发和修改 Dify 前端代码。

## 📋 环境要求

在开始之前，请确保你的开发环境满足以下要求：

- **Node.js**: >= v22.11.0
- **pnpm**: v10.x
- **操作系统**: Windows / macOS / Linux

## 🚀 快速开始

### 1. 安装依赖

进入 `web` 目录并安装项目依赖：

```bash
cd web
pnpm install
```

### 2. 配置环境变量

创建 `.env.local` 文件（如果不存在），并配置必要的环境变量：

```bash
# 从示例文件复制（如果存在）
cp .env.example .env.local
```

在 `.env.local` 中配置以下变量：

```env
# 开发环境标识
NEXT_PUBLIC_DEPLOY_ENV=DEVELOPMENT

# 部署版本（自托管）
NEXT_PUBLIC_EDITION=SELF_HOSTED

# 后端 API 地址（控制台）
NEXT_PUBLIC_API_PREFIX=http://localhost:5001/console/api

# Cookie 域名（前后端在不同子域名时需要设置）
NEXT_PUBLIC_COOKIE_DOMAIN=

# 后端 API 地址（Web App）
NEXT_PUBLIC_PUBLIC_API_PREFIX=http://localhost:5001/api

# Sentry 错误追踪（可选）
NEXT_PUBLIC_SENTRY_DSN=
```

> ⚠️ **重要提示**:
> - 确保 `NEXT_PUBLIC_API_PREFIX` 和 `NEXT_PUBLIC_PUBLIC_API_PREFIX` 指向正确的后端 API 地址
> - 如果前后端运行在不同子域名，需要设置 `NEXT_PUBLIC_COOKIE_DOMAIN`，且必须在同一顶级域名下

### 3. 启动开发服务器

运行开发服务器：

```bash
pnpm dev
```

开发服务器将在 [http://localhost:3000](http://localhost:3000) 启动。

> 💡 **提示**: 开发服务器使用 Turbopack 进行快速热重载，修改 `app` 目录下的文件会自动更新页面。

## 📁 项目结构

主要开发目录：

- `app/` - Next.js App Router 页面和组件
- `app/components/` - React 组件
- `app/i18n/` - 国际化文件
- `utils/` - 工具函数
- `scripts/` - 构建和开发脚本

## 🛠️ 开发工作流

### 修改代码

1. 在 `app/` 目录下编辑文件
2. 保存后，Next.js 会自动重新编译并刷新浏览器
3. 查看浏览器控制台和终端输出以获取错误信息

### 代码质量检查

在提交代码前，运行以下命令确保代码质量：

```bash
# 修复 ESLint 错误
pnpm lint:fix

# TypeScript 类型检查
pnpm type-check:tsgo

# 运行单元测试
pnpm test
```

### 组件开发

使用 Storybook 进行独立组件开发：

```bash
pnpm storybook
```

Storybook 将在 [http://localhost:6006](http://localhost:6006) 启动。

### 组件复杂度分析

在编写测试前，分析组件复杂度：

```bash
pnpm analyze-component app/components/your-component/index.tsx
```

## 🧪 测试

### 运行测试

```bash
# 运行所有测试
pnpm test

# 监听模式运行测试
pnpm test:watch

# 生成测试覆盖率报告
pnpm test:coverage
```

### 测试示例

参考以下文件了解如何编写测试：

- `utils/classnames.spec.ts` - 工具函数测试示例
- `app/components/base/button/index.spec.tsx` - 组件测试示例

详细测试指南请查看：[web/testing/testing.md](./testing/testing.md)

## 🌐 国际化

### 检查国际化

检查代码中是否有硬编码的文本：

```bash
pnpm i18n:check
```

### 自动生成国际化

自动生成国际化键值：

```bash
pnpm i18n:gen
```

> 📝 **注意**: 所有用户可见的文本必须使用 `web/i18n/en-US/` 中的国际化文件，避免硬编码。

## 🔍 调试

### VS Code 调试配置

如果使用 VS Code，可以配置调试：

1. 确保 `.vscode/settings.json` 存在（从 `settings.example.json` 复制）
2. 使用 VS Code 的调试功能连接到开发服务器

### Chrome DevTools

开发服务器已启用 Node.js 调试模式，可以在 Chrome DevTools 中调试：

1. 打开 Chrome 并访问 `chrome://inspect`
2. 点击 "Open dedicated DevTools for Node"
3. 设置断点并开始调试

## 🐛 常见问题

### 1. 端口被占用

如果 3000 端口被占用，Next.js 会自动尝试下一个可用端口。

### 2. 依赖安装失败

确保使用正确的 pnpm 版本：

```bash
pnpm --version  # 应该是 10.x
```

如果版本不对，安装指定版本：

```bash
npm install -g pnpm@10.26.2
```

### 3. 类型错误

运行类型检查：

```bash
pnpm type-check:tsgo
```

### 4. API 连接失败

检查 `.env.local` 中的 API 地址是否正确，确保后端服务正在运行。

### 5. 热重载不工作

- 检查文件是否在 `app/` 目录下
- 尝试重启开发服务器
- 清除 `.next` 缓存目录

## 💡 开发技巧

1. **使用 TypeScript**: 项目使用严格 TypeScript 配置，避免使用 `any` 类型
2. **遵循代码规范**: 使用 `pnpm lint:fix` 自动修复格式问题
3. **组件测试**: 在修改组件前先分析复杂度，编写适当的测试
4. **国际化优先**: 所有用户可见文本都应使用国际化，不要硬编码
5. **类型安全**: 充分利用 TypeScript 的类型系统，编写类型安全的代码
